# HEXORBIT（星核轮转）微信小游戏版

这是原网页版 Hextris 的微信小游戏移植版本，游戏中文名为“星核轮转”，英文名为“HEXORBIT”。**本仓库根目录即小游戏项目目录**，可直接用微信开发者工具导入。

## 已实现的功能

- 完整保留六边形旋转、方块下落、同色 3 连消除、连击倍率、难度递增
- 背景音乐、旋转/落块/消除/结束音效、消除震动反馈
- 设置面板可分别开关背景音乐、游戏音效、震动反馈，设置会保存
- 暂停页可“保存并返回首页”，结束页可“返回首页”，都有二次确认
- 微信好友排行榜：开放数据域 + 微信托管数据，不接自建服务器
- 结算页展示本次得分、历史最高、好友排名、击败好友数
- 只在新纪录时上报云存储，每个用户只保留一个历史最高分
- 结算页可生成带分数的分享卡片，分享与否完全由玩家决定
- 分享卡片带 `challengeScore` 参数，好友点开可直接接受挑战并看到挑战结果
- 首次启动隐私提示、好友排行榜说明分开处理；接入微信官方 `wx.requirePrivacyAuthorize`，拒绝时隐藏排行榜入口，游戏正常游玩
- 异常高分阈值 + 上传频率校验，避免离谱分数进入排行榜
- 广告占位接入：全局开关默认关闭；开启后结算页可看激励视频复活（单局限 1 次），Banner 仅结算页底部展示
- 纯 Canvas 渲染，不依赖图片、字体文件、DOM、jQuery
- 微信小游戏 API：
  - `wx.createCanvas()` 全屏画布
  - `wx.onTouchStart` 触屏操作
  - `wx.getWindowInfo()` 屏幕尺寸、DPR、安全区适配
  - `wx.setStorageSync` 自动存档 / 最高分 / 音频设置
  - `wx.createInnerAudioContext` 背景音乐和音效
  - `wx.shareAppMessage` 分享挑战卡片
  - `wx.vibrateShort` 消除震动反馈
  - `wx.onHide` / `wx.onShow` 切后台自动暂停
- 开始页、暂停页、玩法说明、结束页、好友排行榜全部用 Canvas 绘制
- 首页始终只有一个主按钮；有存档时“继续上一局”收成下方小文字链，超过 3 小时的旧存档自动忽略
- 竖屏、刘海屏安全区适配，高清屏 DPR 适配

## 颜色数量与难度

开局 3 色缓冲约 15 秒，之后 4 色，难度达到 20 后加入第 5 色（只增不减）。颜色变化只影响“新方块可能是什么颜色”，不影响已有方块与消除判定。

| 阶段 | 触发条件 | 可用颜色 |
| --- | --- | --- |
| 开局缓冲 | 难度 < 2（约 15 秒） | 3 色 |
| 常规 | 难度 2 – 19 | 4 色 |
| 后期 | 难度 ≥ 20（约 2 分钟） | 5 色 |

- 阈值：`core/colors.js` 的 `STEPS`，第一个是缓冲结束点，第二个是第 5 色
- 色值：`js/state.js` 的 `COLORS`，前 4 个常规使用，第 5 个是解锁色
- 难度门槛来自实测：主动消除的玩家约 2 分钟到达，几乎不消除约 3 分钟
- 真机快速验证：控制台执行 `HEXORBIT.difficulty(30)`（直接跳到后期）或 `HEXORBIT.colorCount(5)`（强制 5 色）
- 运行时改阈值：`HEXORBIT.unlockAt(30)`，`HEXORBIT.unlockAt(0)` 恢复默认

## 在微信开发者工具中运行

1. 下载并安装 [微信开发者工具](https://developers.weixin.qq.com/miniprogram/dev/devtools/download.html)。
2. 打开开发者工具，选择 **小游戏** → **导入项目**。
3. 项目目录选择本仓库根目录。
4. AppID：
   - 当前 `project.config.json` 里已经填了 AppID 时会自动沿用。
   - 如果为空或显示 `touristappid`，本地预览可以先用游客模式；真机调试或上传需要填你自己的小游戏 AppID。
5. 点击 **编译**，即可在模拟器中运行。
6. 点击 **预览** 生成二维码，用微信扫码真机测试。

> 注意：`touristappid` 只能用于本地体验，不能上传发布。正式上传前请确认 `project.config.json` 里的 `appid` 是你自己的小游戏 AppID。

## 上传发布

1. 在微信公众平台注册小游戏账号，拿到 AppID。
2. 确认 `project.config.json` 中的 `appid` 是你的小游戏 AppID（当前文件里已有值时不要误删）。
3. 开发者工具中点击 **上传**，填写版本号和备注。
4. 登录微信公众平台 → 版本管理 → 提交审核。
5. 审核通过后发布。

建议在公众平台补充：

- 小游戏类目（休闲益智）
- 隐私保护指引（不接入自建服务器；好友排行榜使用微信托管数据和好友关系）
- 用户协议
- 分享文案和截图

## 操作方式

- 首页：英文名 HEXORBIT、中文名“星核轮转”
- 首页：灰色六边形按屏幕可用高度自适应放大，主按钮挂在六边形下沿，高屏手机不会出现大片空白
- 首页：主按钮“开始游戏”/“新游戏”；有存档时下方显示小字“继续上一局”
- 首页：首次进入（无存档且从未得分）时显示一次操作提示
- 首页底部：玩法说明 / 好友排行榜 / 设置
- 游戏中：点击屏幕左半边 / 右半边，旋转六边形
- 左上角：暂停
- 暂停页：继续游戏 / 重新开始 / 玩法说明 / 设置 / 保存并返回首页
- 玩法说明和设置统一收进暂停页，游戏中不再显示额外图标按钮
- 结束页：本次得分、历史最高、好友排名、击败好友数；再来一局 / 分享挑战 / 返回首页

## 返回首页

- 暂停页点击“保存并返回首页”：会先保存当前局面，再回到首页，首页会出现“继续上一局”小字链。
- 结束页点击“返回首页”：本局已经结算，回到干净的首页，最高分会保留。
- 两个入口都会先弹出同风格确认框，避免误触。
- 返回首页后背景音乐恢复，点击“继续上一局”或“新游戏”即可重新进入。
- 首页主按钮始终只有一个：没有存档时是“开始游戏”，有存档时是“新游戏”。
- 超过 3 小时的旧存档会自动忽略，避免首页长期挂着“继续上一局”。需要改时长可以调整 `js/save.js` 里的 `SAVE_MAX_AGE`。

## 好友排行榜

排行榜使用微信开放数据域，不接自建服务器：

- 主域通过 `wx.setUserCloudStorage` 写入自己的历史最高分
- 开放数据域通过 `wx.getFriendCloudStorage` 读取好友历史最高分
- 云存储只有一个 key：`hextris_best_v1`
- 只有本地历史最高分被打破时才尝试上报；启动时如果本地纪录高于云端，会补同步一次
- 上报前会尝试读一次自己的云端最高分，避免低分覆盖高分
- 好友数据只在开放数据域内使用，不把昵称/头像原始数据传回主域

首页底部“好友排行榜”打开好友榜（首版显示前 8 名 + 自己）；结算页展示：

- 本次得分
- 历史最高
- 好友排名 `#N / M`
- 击败好友数
- 新纪录时显示“新纪录！”，下方显示“超越 XX 位好友”

注意：

- 只有玩过并写入过云存储的微信好友才会出现在榜单里
- 好友未授权头像昵称时，会显示默认头像/“微信用户”
- 没有好友数据时显示“暂无好友上榜，邀请好友一起玩”
- 如果 `wx.getUserCloudStorage` 在当前基础库主域不可用，会退化为只按本地最高分判断是否上报，不会影响游戏

## 分享卡片与挑战闭环

结算页“分享挑战”会生成一张 5:4 分享图，包含：

- HEXORBIT 标题
- 本次得分
- 文案“我拿到 XX 分，来挑战我！”

分享参数同时带上：

```text
challengeScore=分数
```

好友点开后：

1. 首次进入先走隐私提示
2. 弹出“好友挑战 / 目标分数 1234”
3. 接受挑战会开始新的一局；如果本地有存档，会提示存档将被替换
4. 结算页显示挑战成功/失败、超出/还差多少分
5. 可以继续“分享挑战”，把新分数分享回去

分享按钮不是强制流程，不分享也能正常重开/返回首页。分享图生成失败时会退化为纯文字分享。

## 隐私与授权

- 首次启动展示自定义隐私说明面板，说明本地存储、好友排行榜使用的微信托管数据和好友公开游戏数据
- 面板底部有“查看《…隐私保护指引》”链接，调用 `wx.openPrivacyContract` 打开后台配置的官方指引
- 点“同意并继续”后调用 `wx.requirePrivacyAuthorize` 触发微信官方隐私弹窗；未配置隐私指引或老版本基础库会直接跳过
- 启动时用 `wx.getPrivacySetting` 查询 `needAuthorization`：如果微信侧尚未同意（例如后台新增了收集类型），会重新展示隐私面板
- 隐私提示与排行榜提示是两个独立面板
- 首次点击排行榜会弹出“好友排行榜”说明；拒绝后隐藏排行榜入口，游戏仍可正常游玩
- 排行榜只使用微信开放数据域的好友公开游戏数据，不申请 `scope.userInfo`，也不获取手机号、位置等其它信息
- 隐私或排行榜被拒绝时：
  - 不加载好友排行榜
  - 不读写云端最高分
  - 本地游戏进度和设置仍然可用
- 隐私/排行榜状态保存在本地，不会每次启动重复弹窗
- 提审前仍需在微信公众平台「设置 → 服务内容声明 → 用户隐私保护指引」声明：设备信息（屏幕尺寸，用于适配）、用户信息（好友榜单的头像昵称）、朋友关系、游戏数据（最高分）

## 广告（默认关闭）

`js/ads.js` 是广告占位接入层，默认 `enabled: false`，上线时不会调用任何广告接口。

- 总开关和广告位都在 `js/ads.js` 顶部：

```js
var config = {
  enabled: false,          // 达标后改 true
  rewardedUnitId: '',      // 激励视频广告位 ID
  bannerUnitId: '',        // Banner 广告位 ID
  revivePerRun: 1,
  ...
};
```

- 开通流量主后：填入两个 `adunit-` 开头的广告位 ID，把 `enabled` 改成 `true` 即可生效，不需要改其它代码。
- **激励视频**只出现在结算页：用户主动点击“看完整视频，原地复活”，单局最多 1 次；保留分数和难度，清空棋盘继续本局。
- **Banner**只在结算页底部展示，使用 `overRevive` 上方的预留区域；对局中、暂停页、帮助/设置/授权/排行榜等任何其它状态都会立即隐藏。
- 用户没看完就关闭、广告无库存、加载失败、接口异常都会按“不可用”处理：只显示一行提示，结算页按钮照常可用，不消耗复活次数。
- Banner 高度以 `onResize` 返回的真实值为准，结算面板改为贴底布局，按钮始终在 Banner 上方；设备太矮、放不下面板时自动放弃本次 Banner，优先保证面板完整。
- 文案只描述“看完整视频、原地复活”，不涉及充值、购买、金币或付费，也不做强制分享。
- 广告开关关闭时，`layout.overRevive` 仍存在但不会绘制，结算页布局与之前完全一致。

预览环境的 `wx.createRewardedVideoAd` / `wx.createBannerAd` 是 `tools/build-preview.js` 里的 mock，只用于浏览器调试，不参与上传。

## 异常高分校验

`js/guard.js` 提供简单的阈值 + 频率校验：

- 单局分数必须是 0 到 1,000,000 之间的整数
- 超过阈值不写入本地最高分，也不上传排行榜
- 两次上传至少间隔 30 秒
- 1 小时内最多上报 5 次
- 启动时如果云端记录异常，也不会用异常本地分数覆盖

结算页会显示“成绩异常，未计入排行榜”。阈值和频率可以在 `js/guard.js` 顶部调整。

## 和网页版的差异

为了保证能直接上微信小游戏，做了以下调整：

- 删除 `jQuery`、`keypress`、`Hammer`、`JSONfn`、`Cookies`、`sweet-alert` 等浏览器依赖
- 删除 DOM UI，改为 Canvas 绘制
- 删除远程脚本 `hextris.io/a.js`
- 删除向 `http://54.183.184.126/` 上报分数的逻辑
- 删除 Google Analytics
- 存档从“序列化带函数的游戏对象”改为纯 JSON 数据
- 连击计时从全局 `settings.comboTime` 改为每个六边形自己的 `comboTime`，读档后不会丢失
- 修正了原版字体字符串拼接、部分出块车道范围等小问题

## 参数调优

主要在 `js/state.js` 的 `settings` 里：

```js
startDist: 227,              // 方块出生距离
creationDt: 60,              // 方块出现动画时长
baseHexWidth: 87,            // 中心六边形大小
baseBlockHeight: 20,         // 方块厚度
rows: 7,                     // 每条边最多堆几层，超过即结束
speedModifier: 0.73,         // 影响难度增长速度
creationSpeedModifier: 0.73, // 出块速度
comboTime: 310,              // 初始连击窗口
difficultyMax: 45,           // 最终难度上限（原版 35）
difficultyGrowth: 2.5        // 难度增长速度倍率
```

当前难度上限 45，最大下落速度值 `1.5 + 45/15*3 = 10.5`（原版 35 时是 8.5）。  
按当前代码纯时间约 5.3 分钟到 35、约 6.3 分钟到 45；实际消除方块会额外增加难度，通常会明显更早到顶。

颜色在 `js/state.js` 的 `COLORS` 数组里修改。

## 音频说明

- 背景音乐和音效都是程序合成的 WAV，位于 `audio/` 目录，没有版权问题，可以直接替换。
- 音量在 `js/audio.js` 里调整：`bgm` 默认 `0.26`，音效约 `0.10 ~ 0.24`。
- 背景音乐循环播放；进入暂停、帮助、设置、结束页时会自动暂停，继续游戏时恢复。
- 如果觉得 WAV 包体偏大，可以把自己的 mp3 放到 `audio/`，然后把 `js/audio.js` 里的文件名改成 `.mp3`。
- 重新生成当前音频：

```powershell
node tools/generate-audio.js
```

- iOS 上默认遵守系统静音开关（`obeyMuteSwitch: true`）。
- `project.config.json` 里的 `ignoreUploadUnusedFiles` 和 `project.private.config.json` 里的 `ignoreDevUnusedFiles` 都已设为 `false`，避免音频文件因为不是 `require` 引入而被当成未使用文件漏传。
